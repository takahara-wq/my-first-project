AI-Driven School 課題 ｜ 面倒な報告の自動化

「週次 現場・見積・請求サマリー」を自動生成して共有する

毎週繰り返し発生する 現場進捗・見積・請求・証憑整理 の報告を、 データ取得→整形→要点化→共有まで一気通貫で自動化するツールの設計図です。

報告ツールの画面（スクリーンショット）

※個人情報・機密は各自モザイク

ここにスクリーンショットを配置

例：週次レポート（現場/見積/請求/次アクション）

画面は「誰が見ても一目で分かる」ことを優先し、今週の重要点・数字・次アクション を同じ場所に固定配置する。

報告を自動化する4つのパーツ

自動化の設計は「トリガー／ソース元／処理する場所／届ける先」を先に固定し、 実装の迷子を防ぎます。

TRIGGER
トリガー
  • 毎週（金）17:30 に自動実行（例：GitHub Actions / Cursor Automation）
  • または「生成ボタン」を押して手動実行（最初はここからでOK）
SOURCE
ソース元
  • 案件/見積/請求の一覧（例：スプレッドシートCSV）
  • 証憑（メール/LINE受領PDF）の保管フォルダ（例：Share/Drive）
PROCESS
処理する場所
  • CSVを読み込み → 集計（件数/金額/未処理）
  • AIで「要点/リスク/次アクション」を文章化
  • 完成形HTML（テンプレ）へ流し込み
  • バリデーション：必須項目が欠けたら停止
DELIVERY
届ける先
  • Surgeで公開してURL共有（閲覧専用リンク）
  • 必要なら：メール/Slack/LINEへURLを自動送信

工夫したポイント（提出用）

  • 完成形のHTMLを先に固定し、AIの出力ブレを抑える（テンプレに流し込む設計）。
  • 4パーツを先に決めて、実装で迷子にならないようにした（トリガー/ソース/処理/届け先）。
  • バリデーション（必須項目欠け・数値欠落）を入れて、誤報告を防ぐ設計にした。
  • 共有はSurgeのURLに統一し、メール/チャットにはURLだけを流す（情報の最新版が常に1箇所）。
  • 機密配慮：スクショはモザイク前提、データ元はCSV/フォルダ分離で管理する。
提出の一言（発表でも使える）
