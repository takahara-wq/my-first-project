ハイランドハウス顧客ポータル

顧客情報・工事履歴・書類管理を一元化する仕組み

株式会社ハイランド・ハウス

Next.js TypeScript Tailwind CSS shadcn/ui Prisma SQLite Vercel

リフォーム会社では、次の情報が複数箇所に分散保存されている。

  • ・顧客情報
  • ・工事履歴
  • ・見積書
  • ・契約書
  • ・保証書
  • ・工事写真

そのため「どこに何があるか分からない」という課題がある。

Before（現状）

  • ・顧客情報と書類が分散
  • ・工事履歴を探すのに時間がかかる
  • ・担当者しか場所が分からない

After（本ツール導入後）

  • ・顧客→工事→書類が一画面で分かる
  • ・顧客検索だけで必要情報を表示
  • ・情報共有が容易になる

現在の4ペイン画面（業務ソフト風レイアウト）

ペイン1

顧客ポータル

検索・あいうえお・一覧

ペイン2

顧客情報

名前・住所・電話・担当者

ペイン3

工事履歴

契約日・内容・進捗

ペイン4

顧客バインダー

楽々ライブラリ風・棚表示

↑ workspace-screenshot.png を同フォルダに置き、imgタグのコメントを外してください

Prisma スキーマで3テーブルに正規化 ／ リロード後もデータが保持される

保存先

SQLite

prisma/dev.db

理由

  • ✓無料で利用できる
  • ✓Cursorとの相性が良い
  • ✓学習コストが低い
  • ✓Vercelとの連携が容易
  • ✓データ永続化の学習に適している

データの流れ

画面（4ペイン操作）
↓
SQLite（prisma/dev.db）
↓
リロード（F5）
↓
データ保持 ✅
  • 1 4ペイン構成 — 業務ソフトと同じ横並びレイアウト
  • 2 顧客→工事→書類を可視化 — 左から右へ流れが一目で分かる
  • 3 楽々ライブラリ風バインダー — 棚に並ぶ書類で直感的に操作
  • 4 色分けされた画面構成 — 紫・橙・青・緑でペインを識別
  • 5 業務ソフトらしいUI — 一覧型・余白多め・見やすい文字サイズ
  • ▸ Prisma設定 — スキーマ定義・Client生成・バージョン調整
  • ▸ SQLite構築 — .env設定・db push・シードデータ投入
  • ▸ リロード後のデータ保持 — Server Actions + revalidatePath
  • ▸ 4ペインレイアウト作成 — 独立スクロール・色分け・連動表示
  • ▸ 顧客バインダーの表現 — 楽々ライブラリ風の棚UI実装
